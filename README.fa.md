# Splunk SendMail
### مدیریت متمرکز گیرندگان اعلان‌های ایمیلی در Splunk

**Splunk SendMail** یک Custom Search Command برای Splunk است که مدیریت گیرندگان ایمیل Alertها و Searchها را متمرکز می‌کند.

## مسئله‌ای که حل می‌کند

فرض کنید در یک سازمان ۷۰۰ Alert زمان‌بندی‌شده وجود دارد و تعداد زیادی از آن‌ها باید برای تیم SOC، زیرساخت یا مدیران ایمیل ارسال کنند.

اگر نیرویی به سازمان اضافه شود، از سازمان خارج شود یا مسئولیتش تغییر کند، آیا منطقی است که مدیر Splunk تک‌تک Alertها را باز کند و گیرندگان ایمیل را دستی تغییر دهد؟ این کار زمان‌بر، مستعد خطای انسانی و دشوار برای نگهداری است. ممکن است یک Alert فراموش شود و همچنان برای آدرس قدیمی ایمیل بفرستد.

راهکار این پروژه، جدا کردن منطق Alert از فهرست گیرندگان است:

- در SPL فقط نام یک گروه مانند `soc` یا `infra` نوشته می‌شود.
- آدرس اعضای هر گروه در یک فایل مرکزی نگهداری می‌شود.
- هنگام اجرای دستور، گروه از فایل خوانده و به فهرست گیرندگان تبدیل می‌شود.
- ارسال ایمیل با قابلیت داخلی Splunk یعنی `sendemail` انجام می‌شود.

در نتیجه، اگر اعضای SOC تغییر کنند، کافی است بخش `[soc]` در فایل مرکزی به‌روزرسانی شود؛ نیازی نیست صدها Alert را ویرایش کنید.

## قابلیت‌ها

- مدیریت متمرکز گروه‌های گیرنده در یک فایل متنی.
- پشتیبانی از چند گروه در یک دستور، مانند `soc,infra`.
- حذف آدرس‌های تکراری در یک گروه یا بین چند گروه انتخاب‌شده.
- اعتبارسنجی ساختار نام گروه‌ها و قالب آدرس‌های ایمیل.
- رد کردن گروه ناشناخته، گروه خالی، آدرس نامعتبر و آدرس خارج از ساختار گروه‌بندی.
- عدم نیاز به راه‌اندازی مجدد Splunk برای تغییرات فایل گیرندگان؛ فایل در زمان اجرای دستور خوانده می‌شود.
- استفاده از تنظیمات ایمیل داخلی Splunk و عدم نگهداری SMTP password در کد اپلیکیشن.
- استفاده از session key ارائه‌شده توسط Splunk برای فراخوانی REST API داخلی.
- تعریف دستور به‌عنوان risky command با `is_risky = true`، چون ارسال ایمیل یک عملیات دارای اثر جانبی است.

## نکته مهم درباره احراز هویت

این اپلیکیشن برای اتصال به SMTP، نام کاربری و رمز عبور جداگانه‌ای در کد خود دریافت یا ذخیره نمی‌کند. ارسال از طریق تنظیمات ایمیل خود Splunk انجام می‌شود.

با این حال، اجرای دستور همچنان در بستر احراز هویت و مجوزهای Splunk قرار دارد. اپلیکیشن از session key ارائه‌شده توسط Splunk برای درخواست REST استفاده می‌کند. بنابراین منظور از «بدون احراز هویت جداگانه» فقط نبود credential مستقل SMTP در این اپلیکیشن است؛ نه حذف احراز هویت یا کنترل دسترسی Splunk.

## ساختار فایل گیرندگان

مسیر:

```text
$SPLUNK_HOME/etc/apps/splunk_sendmail/lookups/Email_bank.txt
```

نمونه:

```ini
[soc]
soc1@example.com
soc2@example.com

[infra]
admin1@example.com

[management]
manager@example.com
```

آدرس‌های واقعی سازمان را در مخزن عمومی GitHub قرار ندهید.

## نمونه استفاده

ارسال به یک گروه:

```spl
| makeresults
| sendmail to=soc title="SOC Test" body="Test notification."
```

ارسال به چند گروه:

```spl
| makeresults
| sendmail to=soc,infra title="Infrastructure Alert" body="Please investigate."
```

استفاده در انتهای جست‌وجوی Alert:

```spl
index=security sourcetype=your_security_source
| where severity="high"
| stats count by host, signature
| sendmail to=soc title="High Severity Alert" body="A high-severity event was detected."
```

تغییر اعضای گروه فقط با ویرایش فایل مرکزی انجام می‌شود و اجرای بعدی دستور، محتوای جدید را می‌خواند.
